## Entry points and architecture

| File | Responsibility |
| --- | --- |
| `review-2026-10/index.html` | Current layout, exact hero copy, filters and script/style references |
| `review-2026-10/app.js` | DOM rendering, hash routes, search, filters, cards/list/map, focus cards and profiles |
| `review-2026-10/review.css` | Review styling and responsive overrides, including SVG arrows |
| `review-2026-10/entries.json` | Public runtime data snapshot; loaded on startup |
| `review-2026-10/directory-review.csv` | Separate human-review export; keep consistent with runtime data |
| `review-2026-10/media/` | Three optimized focus-card images and publisher logos |
| `assets/manifest.json`, `assets/` | Shared slug-to-artwork mapping, images and local Geist fonts |
| `styles.css`, `match.css` | Shared base styling; changing these also changes the original website |
| `vendor/leaflet/` | Bundled Leaflet 1.9.4 JavaScript and CSS |
| Root `index.html`, `app.js`, `entries.json` | Preserved original public website |

The app is plain HTML/CSS/JavaScript, with no bundler or framework. `boot()` fetches JSON and the shared artwork manifest, then sets up filters. `matches()` applies all active filters; `renderResults()` separates existing `election: true` records into expanded In focus cards and removes them from the lower results, so they appear once. Empty focus sections hide. Filtering still applies to focus resources. The list reuses card markup; the map uses source coordinates and links to profiles.

Routes: `#/` (home), `#/directory` (directory), `#/directory/<slug>` (profile), `#/directory?focus=election` (focus shortcut). Most filter state is in memory and is not serialized in the URL. The election shortcut clears conflicting filters. Map tiles come from OpenStreetMap; preserve attribution. Multiple records sharing coordinates cluster, then fan out at higher zoom; positions are approximate and must not be presented as precise addresses.

## Data and taxonomy

Two records with conflicting descriptions were withheld from the review, rather than rewriting the original. The review also merges eligible public records from a second directory; counts are not a count of net-new source rows. Do not re-import withheld/private/conflicting records without review.

`entries.json` is the runtime source of truth **for this published snapshot**, not a live source database. The CSV is not automatically regenerated by the app. There is no public import/generation pipeline in this repository. ## Run, test and deploy

Use the root-server commands in [README.md](README.md). No compile/build step is needed. Keep `../assets/`, base CSS and vendored Leaflet paths available to the review directory.

Run `python3 scripts/verify_handoff.py` and the two Node syntax checks before delivery. The Python check validates unique slugs, public field/URL boundaries, taxonomy values, CSV consistency, local assets and original snapshot preservation. It is a regression aid, not proof that every organization field is accurate or approved. `--live` adds unauthenticated HTTP byte comparisons against this checkout.

Browser smoke checks:

1. Test 390px mobile, 768px tablet, 1280–1440px desktop and a wide desktop window; look for overflow and wrapping after resizing.
2. Confirm exact hero copy, all three credited focus images, readable fallback when an image fails, SVG arrows and visible keyboard focus.
3. Search, select a broad lens/domain/source, clear filters, and open the election shortcut with conflicting filters active. Focus resources should appear once and disappear when excluded.
4. Switch cards/list/map, paginate, open a profile, return, and follow source/resource links. Confirm map attribution and approximate-position messaging.
5. Confirm removed display labels do not return, while category names, source credits and metadata/export fields remain.

Pages currently uses the legacy **`main` branch / repository root** source. An approved push to `main` automatically deploys both URL paths. There is no custom deployment workflow in this repo. Review the diff and obtain the owner's publication approval before pushing; do not change Pages settings or repository visibility as part of routine maintenance. Verify the exact remote SHA and successful Pages build, then run live checks and inspect mobile/desktop in a browser. Update `app.js`/`review.css` query versions in the review HTML when changing those files, to avoid stale cached UI.

## Privacy and maintenance boundaries

- This repository and its Git history are public. Include only reviewed public organization/resource fields and public links. Deleting sensitive material in a later commit does not remove it from history.
- Keep private source spreadsheets/documents, editor links, chat excerpts, phone numbers/emails, contacts, connection/membership notes, nonpublic flags/rows, credentials and research/audit scratch files outside the repo. Do not copy a parent workspace or private source checkout into it.
- Do not infer publication permission from a shared document or a fetchable URL. Respect explicit nonpublic and for-web flags. When permission is unclear, omit the field/row and ask the owner through the private workflow.
- Deduplicate by verified identity, preserve provenance, and quarantine conflicting descriptions. Some source matches/cells were unresolved in the earlier release; do not assume historical issues are resolved because a name is present.
- Work on a branch and review changes to public JSON/CSV independently of visual changes. Keep a private audit of source-to-public transformations. Refresh data and CSV together; re-run validation and have the owner review ambiguous mappings.
- Protect the root snapshot. Scope routine work to `review-2026-10/`; shared stylesheet/assets changes affect both versions and require an explicit plan.

## Known gaps and rights considerations

- This is a review prototype, not a live integration. No authenticated accounts, server-side editing, submissions, database, scheduled refresh or automatic event collection exists.
- No dated events are currently verified for publication. The event directory is an external link. Code can hide entries with an elapsed `endsAt`, but no current records carry that field; future dated events need a defined timestamp/timezone and validation.
- Public resource links were checked on October 31, 2026. They can change. The heat-map image is a static official preview; open the publisher's site for current interactive data. Voting Rights Lab specifies nonpartisan educational use; preserve that restriction and attribution.
- Focus images use the federal-guide header (Brennan Center + Protect Democracy), extracted Community Resilience co-publisher logos (Protect Democracy + Over Zero), and Voting Rights Lab's official social graphic. The owner approved publication after being told reuse permissions were unconfirmed. **No blanket image/logo reuse license has been obtained; credits do not grant rights.** Keep both co-publishers visible and do not imply endorsement.
- No repository-wide LICENSE or bundled third-party license inventory was present at audit. Do not assume an open-source license for this code, fonts, images or descriptions. Review Leaflet's upstream license/notice requirements and font/image provenance before redistribution or reuse beyond this handoff.
- Search is client-side substring matching. Most filter state is not shareable by URL. Data quality and coordinates vary; some records have no coordinates and do not appear on the map. External tiles and links can fail independently of the static site.
- The public snapshot is sufficient to run and modify the existing site. It does **not** contain the private original project, raw source data, private communications, or the full import/audit tooling. Request those separately from the owner only if needed and authorized.
